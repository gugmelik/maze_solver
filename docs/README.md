# Research documentation

Этот репозиторий посвящён обучению диффузионных моделей и адаптеров для них.
Эта директория хранит общий контекст исследовательского проекта и используется
как долговременная память при работе с агентами.

## Documents

### `TASK.md`

Описание решаемой задачи, которой посвящён репозиторий.


### `ARCHITECTURE.md`

Текущая архитектура репозитория:

- основные компоненты;
- процедура обучения и валидации;
- конфигурация экспериментов;
- важные детали реализации.

### `EXPERIMENTS.md`

Полный журнал экспериментов.

Содержит записи обо всех экспериментах: запланированных, завершённых, неудачных и отладочных.

Для каждого эксперимента должны быть указаны:
- Название эксперимента — уникальное, совпадает с параметром `writer.run_name` каждого рана. Скрипт для запуска этого эксперимента должен располагаться в `scripts/<writer.run_name>.sh`. Название должно быть кратким, описывать суть эксперимента и не содержать пробелов.
- Идея эксперимента — краткое описание того, зачем нужен этот эксперимент, какое изменение вносим, какой параметр варьируем и т. п.
- Бейзлайны — названия других экспериментов, с которыми будут сравниваться результаты текущего эксперимента.
- Ожидаемые результаты — очень краткое описание ожидаемых результатов относительно бейзлайнов.
- Полученные результаты — результаты, полученные на практике относительно бейзлайнов.


### `RESEARCH_LOG.md`

Курируемый журнал научных результатов.

Содержит подтверждённые положительные и отрицательные результаты, но не
содержит подробностей об отладочных запусках и экспериментах, в которых найдены ошибки.
Серии связанных экспериментов могут быть объединены в одну запись. Если `EXPERIMENTS.md` — это преимущественно технический журнал, то здесь собраны научные заметки о том, какие идеи работают, а какие нет.

Для каждого эксперимента или серии экспериментов должны быть указаны:
- Название — должно кратко отражать суть экспериментов.
- Идея — почему мы решили проводить этот набор экспериментов. Можно сослаться на предыдущие эксперименты и указать, какую гипотезу проверяем.
- Бейзлайны — ссылки на другие эксперименты, с которыми логично сравнивать результаты.
- Ожидаемые результаты — описание результатов, ожидаемых от этой серии экспериментов.
- Привязанные эксперименты — список названий из `EXPERIMENTS.md`, которые связаны с этой серией экспериментов.
- Полученные результаты — выводы, которые можно сделать о проверяемой гипотезе.

### `TOOLS.md`

Описание инструментов из `tools/`, предназначенных для анализа экспериментов
и работы агентов.

## Agent roles

### Coding agent

Рекомендуемый контекст:

- `README.md`;
- `TASK.md`;
- `ARCHITECTURE.md`;
- `RESEARCH_LOG.md`;
- `EXPERIMENTS.md`;
- код проекта.

Задачи:

- реализовать код для проверки гипотезы;
- при реализации большого количества новых классов можно создать отдельные конфиги в `src/configs`;
- создать необходимые скрипты для запуска запрошенных экспериментов в `scripts/`. Название каждого скрипта должно соответствовать `writer.run_name` и быть уникальным;
- для каждого эксперимента добавить запись в `EXPERIMENTS.md` по всем описанным выше пунктам, кроме полученных результатов;
- в записи соответствующей серии экспериментов в `RESEARCH_LOG.md` обновить только поле `Привязанные эксперименты`. Больше ничего в `RESEARCH_LOG.md` изменять нельзя.

### Validator agent

Рекомендуемый контекст:

- `README.md`;
- `TASK.md`;
- `EXPERIMENTS.md`;
- `RESEARCH_LOG.md`;
- `TOOLS.md`;
- директории анализируемых ранов.

Задачи:

- проверить полноту и корректность результатов указанных экспериментов;
- сравнить метрики с бейзлайнами;
- если это явно указано в запросе, заполнить результаты и выводы в `EXPERIMENTS.md`;
- не изменять код.

### Debugger agent

Рекомендуемый контекст:

- `README.md`;
- `TASK.md`;
- `ARCHITECTURE.md`;
- `EXPERIMENTS.md`;
- код, конфиги и скрипты запуска проблемных экспериментов.

Задачи:

- найти в коде причины неконсистентных результатов;
- определить, вызван ли результат ошибкой в коде, или, если ошибок нет, объяснить, почему поведение не совпадает с ожиданиями;
- при явном запросе подготовить исправленный эксперимент с новым именем.

### Researcher agent

Рекомендуемый контекст:

- `README.md`;
- `TASK.md`;
- `RESEARCH_LOG.md`;
- `TOOLS.md`;
- релевантные записи из `EXPERIMENTS.md`.

Задачи:

- объединять подтверждённые результаты в `RESEARCH_LOG.md`;
- анализировать положительные и отрицательные результаты;
- формулировать новые гипотезы и серии экспериментов.

## Research workflow

1. Сформулировать гипотезу.
2. Реализовать код, конфиги и скрипты запуска.
3. Добавить запланированные эксперименты в `EXPERIMENTS.md`.
4. Запустить эксперименты.
5. Проанализировать метрики и заполнить результаты.
6. При подозрительных результатах провести отдельный цикл отладки.
7. Перенести подтверждённые выводы в `RESEARCH_LOG.md`.
8. Сформулировать следующие гипотезы и повторить цикл.

## Experiment conventions

Для каждого физического запуска:

- `writer.run_name` должен быть уникальным;
- скрипт запуска должен называться `scripts/<writer.run_name>.sh`;
- артефакты сохраняются в `saved/<writer.run_name>/`;
- конфиг находится в корне директории рана;
- чекпойнты находятся в `checkpoints/`;
- validation-метрики находятся в `metrics/validation.json`.

Повторное продолжение того же запуска через `resume` может использовать прежнее
имя. Новый запуск после изменения кода или исправления ошибки должен получать
новое имя.
